# 全局队列匹配方法学与核对口径

本模块解决容量约束下的全局匹配，避免逐病例贪心造成“先处理者占走稀缺
对照、后处理者即使有更近组合也匹配不上”的问题。所有计算只用 Python
标准库，费用全程精确有理数（`fractions.Fraction`），不使用二进制浮点。

## 1. 建边口径

一条病例-对照边仅在以下条件**同时**成立时建立：

1. 预先登记的分层字段 `stratum` 完全相同；
2. 该病例与该对照在**每个**协变量维度上都已观测（任一为 `null` 即排除，
   缺失绝不按零距离处理）；
3. 每个维度的标准化距离 `|x_case - x_control| / scale` 不超过该维度在
   指定 caliper 集合中的上限。

`scale` 是外部锁定的正数，只读取、不依据匹配结果反调。边费用为

```
cost = Σ_dim weight_dim * ((x_case_dim - x_control_dim) / scale_dim)^2
```

权重是非负有理数且至少一个为正。网络结构为 `源 S -> 病例 -> 对照 -> 汇 T`，
病例弧容量 `k`，对照弧容量 `capacity`，候选边容量恒为 1，因此同一病例
与同一对照不可能重复使用。

## 2. 三层词典序目标

按顺序优化，前一层不被后一层破坏：

1. **最大化总匹配槽数**（最大流）。病例允许只拿到 0..k 个对照；求解器
   不会把这个目标偷换成“最大化完整病例数”。
2. **在最大流解中最小化总费用**（最小费用最大流）。
3. **在仍为最大流且费用最优的解中**，最小化排序后的
   `(case_id, control_id)` 二元组列表的字典序。

### 第 3 层的实现：带严格界证明的扰动法

候选边按字典序编号 `r = 0..E-1`，令 `B = F + 1`（F 为最大流），给边 r
赋予负的超递增扰动 `eps_r = -B^(E-1-r)`，并把整数缩放费用左移 E 位：

```
adjusted_cost_r = (lcm * cost_r) * B^E + eps_r
```

- 任一可行解至多含 F 条边，扰动绝对值之和
  `<= F·B^(E-1) < B^E`；
- 两个解的原始费用若不同，整数缩放后费用差至少为 1，乘以 `B^E` 后
  严格大于任何扰动差。因此扰动**只能在费用相同的解之间决胜**，费用层
  永远支配字典序层；
- 最小化 `Σ eps_r`（负超递增权重）等价于最小化排序边列表的字典序。

`B、E、F` 全部由资料确定，支配关系由 `perturbation_params` 中的断言
机器核验，不是“调一个足够大的罚数”。负权弧由 SPFA（Bellman-Ford 队列
实现）处理；初始网络是 DAG，不存在负环。

提供两个互不共享中间量的数值引擎，优化完全相同的全序：

- `staged`：Fraction 精确有理数，把整数目标整体除以 `lcm`（正数保序）；
- `staged-int`：分母 LCM 等价整数缩放后的纯整数运算。

> 不要用“费用乘大基数 + 正的字典序权重求和”的朴素编码：幂次和实现的
> 是基数计数序，不是题目定义的列表字典序，在等费用竞争解上会给出错误
> 决胜。本仓库的 `equal-cost-competition.json` 就是反例。
> `zero-cycle` 路径（贪心零费用环强制）仅用于小资料诊断，早期锁出的边
> 可能阻断后续更优的环，不保证全局字典序，因此不作为权威实现。

## 3. 精确费用与整数缩放

- JSON 十进制经 `Decimal(str(x))` 转 `Fraction`，对 float 取最短往返
  文本以还原写入时的字面量（如 `0.1 -> 1/10`），不先转二进制浮点；
- `lcm` 是所有候选边费用分母的最小公倍数，整数费用
  `= Fraction 费用 × lcm` 恰为整数，缩放可逆且精确；
- 报告同时给出分数总费用与整数总费用，核对时验证二者严格相等。

## 4. 最小割与费用最优性证书

- **最大流/最小割**：Edmonds-Karp（BFS）求最大流，并输出残余网络中源点
  可达集合与跨越割集的弧；割容量独立重算且必须等于最大流。源侧病例即
  被容量瓶颈阻挡的病例，割上的对照->汇点弧对应用满的对照容量。
- **费用最优性**：在完整候选网络上按报告的流重建残量网络，用多源
  Bellman-Ford（所有节点距离初始化为 0）求对偶可行势能，使每条残量
  正弧满足 `reduced_cost = cost + p[u] - p[v] >= 0`。这等价于残量网络
  无负费用环，即该流是全局最小费用流。核对器独立重算势能并交叉比较。

## 5. 独立核对入口（不只信求解器）

`verify` 与每次 `match` 默认执行的核对全部基于资料与候选边**重新计算**：

1. 匹配边真实存在、排序去重、病例度数 ≤ k、对照度数 ≤ capacity；
2. 独立 Edmonds-Karp 重算最大流，槽数必须一致；
3. 最小割容量 = 最大流，割弧与可达集合独立复算；
4. Fraction 重算费用，整数缩放费用严格等于 `lcm × 分数费用`；
5. 势能 reduced cost 非负，独立 Bellman-Ford 复算并确认无负费用环；
6. 换一个数值引擎（Fraction ↔ 整数）重解，三层结果必须完全一致；
7. 小资料（候选边数 ≤ 阈值）穷举全部可行分配，直接验证三层优先级；
   大资料跳过枚举，只依赖证书与双引擎核对。

## 6. 分析口径与边界

- **效应汇总**只使用拿满 k 个对照的完整病例：每个完整病例先对其对照
  结果取均值，再算病例减对照之差，最后对完整病例等权平均。部分/未匹配
  病例单列，不静默丢弃。
- **复用**报告每个对照的使用次数、服务病例数、槽位份额、容量利用率与
  HHI 集中度；明确不提供把匹配边当独立样本的标准误（`standard_error`
  为 `null`）。
- **平衡表**按匹配前各主体权重 1、匹配后病例权重=槽数、对照权重=被用
  次数，给出各维度加权均值差与标准化均值差；缺失值不参与该维度均值。
  平衡只针对已观测协变量，不能解读为未测混杂已消除。
- **caliper 扫描**对每个预设集合独立重建边与网络并重求全局解，比较
  流量、费用、入选/退出人群；缺失协变量在任何放宽口径下都不能建边。

## 7. 隔离运行

资料是不可信数据。入口脚本 `run_matching.py` 设计为以
`python -I run_matching.py ...` 运行：`-I` 忽略环境变量与当前目录，
脚本只把自身所在的受信代码目录加入 `sys.path`，数据路径始终通过参数
传入，因此数据目录内即使存在同名 `json.py` 等植入文件也不会被导入。
`tests/test_matching.py` 中有对应回归测试。
